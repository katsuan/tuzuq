つづく

自分の記録ボットとつなぐ

つづくは、ふだんは記録をこの端末の中だけに残します。LINE の中で開いたときだけ、自分で用意した GAS（記録ボット LOgBOT の複製）に、○を押した習慣を記録できます。GAS に GitHub の鍵を入れておけば、GitHub に草も付きます。

つづくは、あなたの LINE の鍵・GitHub の鍵を預かりません。送るのは、LINE が出す「本人の確かめ用の印（ID トークン）」と、記録する文と日付だけです。印は確かめに使うだけで、つづくにも GAS にも残りません。

つなぎ方（はじめて）

  1. 持ち主から届いた LOgBOT のリンクを開き、「コピーを作成」
  2. GAS エディタで setupTuzuq を実行（記録のシートを自分のドライブに作ります。今までのシートを使うなら、先に「スクリプト プロパティ」の SPREADSHEET_ID にそのシートの ID を入れる）
  3. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」、実行するユーザー「自分」、アクセスできるユーザー「全員」→ 出てきた URL（…/exec）をコピー
    （画面は、このデプロイでも持ち主しか開けません。つづくからの呼び出しは、確かめた本人のものだけ受けます）
  4. LINE の中でつづくを開き、「💬 LINE でも記録」に 3 の URL を入れる。「持ち主の登録を受けつけました」と出ます
  5. 10分以内に、GAS エディタで adoptTuzuqOwner を実行（実行ログに自分の名前が出ればよい）
  6. つづくで習慣を直し、「送る文」（例：# workout）を決める。今日の○を押すと記録されます

GitHub にも付けるときは、「スクリプト プロパティ」に GITHUB_TOKEN（リポジトリ1つ・Contents の読み書きだけの fine-grained token）、GITHUB_OWNER、GITHUB_REPO を入れます。checkTuzuq で、準備ができているかを見られます。

やめるときは、つづくの URL の欄を空にし、GAS のデプロイをアーカイブします。

受け口の約束（GAS を自分で作る人向け）

つづくは、入れた URL に POST します（本文は text/plain の JSON）。

{ "app": "tuzuq", "v": 1, "op": "record", "idToken": "…", "text": "# workout", "date": "2026-10-24" }
→ { "ok": true, "added": true, "date": "2026-10-24", "github": true }

{ "app": "tuzuq", "v": 1, "op": "days", "idToken": "…", "texts": ["# workout", "# 読書"] }
→ { "ok": true, "days": [["2026-10-20", "2026-10-24"], []], "today": "2026-10-24", "github": true }

うまくいかないとき → { "ok": false, "error": "auth" | "off" | "claim" | "notyou" | "bad" | "day" | "many" | "fail" }
  • 本人の確かめ：POST https://api.line.me/oauth2/v2.1/verify（id_token、client_id＝つづくの LIFF のチャネル ID）。aud・iss（https://access.line.me）・exp を確かめ、sub が持ち主の ID のときだけ受ける。送られてきた userId は使わない
  • 書く：今日（日本時間）の分だけ。同じ日・同じ行動は1件。文は60字・1行まで。1日30件まで
  • 読む：本人の、習慣ごとの記録した日（ここ数か月）だけ。本文・時刻・ID は返さない
  • 返すのは上の決まった言葉だけ（エラーの中身は返さない）。ID トークンは残さない・ログに出さない

URL は秘密ではありません。知られても、確かめなしには何も書けず、何も読めません。ただし、知らない人から渡された URL は入れないでください（入れた先に、確かめ用の印が届きます）。
